## はじめに

- **この記事で得られること**: このブログの各ハンズオン記事(L2TP/IPsecサーバー自作など)に共通して必要になる、環境構築の基本操作をまとめて身につけられます。Proxmox VEでのVM作成、Ubuntu ServerのインストールURL、初回ログイン後の`sudo apt update`や`sudo su -`の意味、`nano`エディタの操作、USキーボードレイアウトでの注意点までを一通りカバーします。
- **対象読者**: インフラの仮想化環境(Proxmox VEなど)やLinuxサーバーの操作が完全に初めてで、これからこのブログのハンズオン記事に取り組みたい方を想定しています。
- **読むのにかかる想定時間**: 約20分(実際に手を動かしながら読む場合はもう少しかかります)

この記事は[『上位1%』シリーズ 全記事ガイド](/sitemap)の一部です。**この記事は「ハンズオンをこれから始める方のための準備運動」に特化した操作マニュアルであり、他の記事のような内部動作の深掘りは扱いません。** Proxmox VEの内部動作(KVM/QEMUの仕組みなど)に興味がある方は[Proxmox VEとは何か](/articles/proxmox-internals-guide)を参照してください。各ハンズオン記事(たとえば[L2TP/IPsecサーバー自作ハンズオン](/articles/l2tp-ipsec-lab-guide))は、この記事で扱う操作ができることを前提に書かれています。

## この記事の使い方

以下の項目は、独立した手順として必要なときに読み返せるようになっています。すでに知っている項目は読み飛ばして構いません。

1. Proxmox VEでVMを作成する
2. OSのインストールメディア(ISO)をダウンロードし、Proxmoxにアップロードする
3. ISOからOSをインストールする(Ubuntu Serverを例に)
4. 初回ログイン後によく使う基本操作(`sudo apt update`、`sudo su -`、`nano`)
5. USキーボードレイアウトでの入力の注意点

## Step 1: Proxmox VEでVMを作成する

Proxmox VEの管理画面(ブラウザで`https://<ProxmoxのIPアドレス>:8006`にアクセス)にログインしたら、対象のノードを選び、右上の**「Create VM」**ボタンから作成ウィザードを開きます。

| 設定タブ | 主な設定項目 | ハンズオン用途での目安 |
|---|---|---|
| General | VM ID、名前 | 名前はハンズオンの内容がわかるものにしておくと後で見分けやすい(例: `l2tp-server`) |
| OS | インストールに使うISOイメージ | Step 2でアップロードしたISOを選択 |
| System | BIOS種別、Qemuエージェントの有無など | 基本的にデフォルトのままで問題ありません |
| Disks | ディスクサイズ、保存先ストレージ | 検証用途なら8〜20GB程度で十分なことが多い(記事ごとの指定に従ってください) |
| CPU | コア数 | 検証用途なら1〜2コアで十分なことが多い |
| Memory | メモリ容量(MB) | 検証用途なら1〜2GB程度で十分なことが多い |
| Network | 接続するブリッジ(通常は`vmbr0`) | 家庭内LANに直結したい場合は`vmbr0`を選択 |

すべてのタブを確認したら「Confirm」で作成を確定します。この時点ではまだVMは起動していません。

## Step 2: OSのインストールメディア(ISO)をダウンロード・アップロードする

**ISOをダウンロードする**: 使用するOSの配布元サイトから、インストール用のISOイメージをダウンロードします。たとえばUbuntu Serverの場合は、[Ubuntuの公式ダウンロードページ](https://ubuntu.com/download/server)からLTS(長期サポート)版を選ぶのが無難です。

**Proxmoxにアップロードする**: Proxmoxの管理画面で、ISOを保存したいストレージ(通常は`local`)を選び、「ISO Images」→「Upload」から、ダウンロードしたISOファイルをアップロードします。ネットワーク越しにISOのURLを直接指定してダウンロードさせる「Download from URL」機能が使える場合は、手元の回線を経由しない分アップロードが速く済むこともあります。

## Step 3: ISOからOSをインストールする(Ubuntu Serverを例に)

Step 1で作成したVMを選び、「Start」で起動したあと、「Console」タブを開くと、VMの画面をブラウザ上で操作できます(noVNCという技術で、リモートデスクトップのようにVMの画面を映しています)。

Ubuntu Serverのインストーラーが起動したら、おおむね次の流れで進みます。

1. **言語選択**: 通常は「English」のまま進めることが多いです(日本語UIは情報が少なく、エラーメッセージも英語のままの方が検索しやすいため)。
2. **キーボードレイアウト選択**: ここで選んだレイアウトが、以降のインストール作業やインストール後の入力方式に影響します。手元が日本語配列のキーボードであれば「Japanese」を選ぶと、キートップの印字通りに入力できます。ここで「English (US)」を選んだ場合の注意点はStep 5(USキーボードレイアウトでの入力の注意点)で扱います。
3. **ネットワーク設定**: `vmbr0`をLANに直結している場合、通常はDHCPで自動的にIPアドレスが割り当てられ、そのまま次に進めます。
4. **ストレージ設定**: 特に理由がなければ「Use an entire disk」のようなデフォルトの案内に従って問題ありません。
5. **プロフィール設定**: サーバー名・ユーザー名・パスワードを設定します。ここで設定したユーザーが、インストール後に`sudo`を使える管理ユーザーになります。
6. **OpenSSH Serverのインストール**: 「Install OpenSSH server」にチェックを入れておくことを強く推奨します。これにより、インストール完了後にSSH経由でVMへ接続できるようになり(Console画面よりコピー&ペーストがしやすく作業効率が上がります)、以降のハンズオン記事の手順もSSH接続を前提に書かれています。
7. **featured server snapsの選択**: ハンズオンで別途指定がなければ、何も選択せずに進めて構いません(あとから`apt`で必要なものを個別にインストールします)。

インストール完了後は再起動を促されます。**再起動前にISOイメージをVMの光学ドライブから取り出す(またはブート順序を変更する)** ことを忘れないようにしてください。これを忘れると、再起動のたびにインストーラーが再度起動してしまいます(ProxmoxのVMの「Hardware」タブ→CD/DVDドライブから、マウントしているISOを取り外せます)。

## Step 4: 初回ログインとよく使う基本操作

再起動後、ネットワーク経由でVMにSSH接続します(Step 3でOpenSSH Serverをインストールしていれば使えます)。

```bash
ssh <Step3で設定したユーザー名>@<VMのIPアドレス>
```

### `sudo apt update`の意味

Ubuntu/Debian系のLinuxは、ソフトウェアを`apt`というパッケージ管理コマンドでインストール・更新・削除します。`apt`は、`/etc/apt/sources.list`(および`/etc/apt/sources.list.d/`以下)に登録された「どのサーバーからどんなソフトウェアが取得できるか」というリポジトリの情報をもとに動作します。

```bash
sudo apt update
```

このコマンドは、**「実際にソフトウェアをインストール・更新する」コマンドではありません。** 各リポジトリに問い合わせて、「現在利用可能なパッケージとそのバージョンの一覧(パッケージインデックス)」を、ローカルのキャッシュとして最新の状態に更新するだけです。この「情報の更新」を先に行っておかないと、実際にソフトウェアをインストールする`sudo apt install <パッケージ名>`が、古い情報のまま動いてしまい、存在しないバージョンを探しに行ったり、最新の依存関係を解決できなかったりします。そのため、**「何かをインストールする前には、まず`sudo apt update`」というのが定石**になっています。

<details>
<summary>apt update / apt upgrade / apt install の違い</summary>

- `sudo apt update`: リポジトリから「利用可能なパッケージ一覧」の情報だけを取得し、ローカルのキャッシュを更新する(何もインストール・変更しない)。
- `sudo apt upgrade`: 現在インストール済みのパッケージのうち、`apt update`で取得した情報の中に新しいバージョンがあるものを、実際に新しいバージョンへ更新する。
- `sudo apt install <パッケージ名>`: 指定したパッケージを新たにインストールする(すでにインストール済みならバージョンアップされることもあります)。

「情報を取得する(update)」と「実際に変更を加える(upgrade/install)」がコマンドとして明確に分かれている点が、他のOSのパッケージ管理と比べたときの`apt`の特徴です。

</details>

### `sudo su -`でrootユーザーになる方法

Ubuntuのインストール時に作成した一般ユーザーは、`sudo`を先頭に付けることで、そのコマンド1回だけを管理者(root)権限で実行できます。一方、複数のコマンドを続けてroot権限で実行したい場合、毎回`sudo`を付けるのは煩雑です。そこで使うのが次のコマンドです。

```bash
sudo su -
```

`su`は switch user(ユーザーを切り替える)の略で、引数を省略するとrootへの切り替えを意味します。**末尾の`-`(ハイフン)を付けるかどうかで挙動が変わる**点に注意してください。

- `sudo su`(ハイフンなし): rootに切り替わりますが、環境変数(`PATH`やカレントディレクトリなど)は元のユーザーのものを引き継ぎます。
- `sudo su -`(ハイフンあり): rootに切り替わり、**環境変数もrootが直接ログインした場合と同じ状態に初期化**します。ホームディレクトリも`/root`に移動します。

多くの場合、`root`本来の環境で作業した方が、パス関連の予期しない不具合を避けられるため、**`-`を付けた`sudo su -`を使うのが一般的**です。作業が終わったら`exit`と入力するか`Ctrl+D`で、元の一般ユーザーに戻れます。

<details>
<summary>補足: sudoとsu、どちらを使うべきか</summary>

実務では、常時rootのシェルに居続ける`su`よりも、**必要なコマンドの直前にだけ`sudo`を付ける運用の方が推奨されます**。理由は、`sudo`を使ったコマンドは`/var/log/auth.log`などに「誰が」「いつ」「何を」実行したかの記録が残りやすく、監査(誰が何をしたかの追跡)がしやすいためです。`sudo su -`でrootに居座り続けると、その後に実行したコマンドが個々の記録として残りにくくなります。このブログのハンズオン記事で`sudo`を都度付けるコマンドが多いのはこのためです。

</details>

### `nano`エディタの基本操作

このブログのハンズオン記事では、`/etc/ipsec.conf`のような設定ファイルの編集に`nano`という、初心者にも扱いやすいテキストエディタを使います。

```bash
sudo nano /etc/ipsec.conf
```

`nano`を起動すると、画面の下部にショートカット一覧が表示されます。`^`はCtrlキーを意味します(例: `^O`はCtrl+Oです)。

| ショートカット | 動作 |
|---|---|
| `Ctrl + O` | 保存(Write Out)。保存先のファイル名を聞かれるので、通常はそのままEnterでOK |
| `Ctrl + X` | 終了(Exit)。編集内容が未保存の場合は保存するかどうか確認される |
| `Ctrl + W` | 文字列検索(Where Is) |
| `Ctrl + K` | 現在の行を切り取り(Cut) |
| `Ctrl + U` | 切り取った内容を貼り付け(Uncut/Paste) |
| 矢印キー | カーソル移動 |

編集を終えて保存せずに終了したい場合(誤って編集してしまった場合など)は、`Ctrl + X`のあとに保存するかを聞かれた画面で`N`(No)を選べば、変更を破棄して終了できます。

## Step 5: USキーボードレイアウトでの入力の注意点

Ubuntu Serverのインストール時にキーボードレイアウトを「English (US)」で選んだ場合、**手元が日本語配列のキーボードだと、キートップに印字されている文字と、実際に入力される文字が一致しない**ことがあります。これは、物理的なキーボードの配列(キーがどこにあるか)と、OSがそのキー入力をどの文字として解釈するか(論理的なレイアウト設定)が、別々の概念だからです。

代表的な差異は次の通りです(キーボードの機種によって多少の違いがあります)。

| 入力したい記号 | 日本語配列で対応するキー | US配列設定時の注意 |
|---|---|---|
| `=`(イコール) | `-`キーの右隣にある専用キー | US配列では`Shift + -`(ハイフンキーのシフト)に割り当てられていることが多く、専用の`=`キーの位置に別の記号が出ることがあります |
| `"`(ダブルクォート) | `2`キーのシフト | US配列では`'`(シングルクォート)キーのシフトに割り当てられています |
| `@`(アットマーク) | `2`キーのシフト(日本語配列で`"`と同じキーの場合あり) | US配列のキーボードでは専用のキー位置が異なります |
| `_`(アンダースコア) | `ろ`キー付近、または`-`のシフト | US配列では`-`キーのシフトに統一されています |

**最も確実な対処法は、物理キーボードが日本語配列であれば、OSの設定でもキーボードレイアウトを「Japanese」に合わせておくことです。** インストール時に誤って「English (US)」を選んでしまった場合も、インストール後に次のコマンドで変更できます。

```bash
sudo dpkg-reconfigure keyboard-configuration
```

対話形式の設定画面が表示されるので、「Keyboard model」は一般的なものを選び、「Country of origin」を「Japan」に変更すると、日本語配列のキーボードで印字通りに入力できるようになります。設定変更後、反映のために一度ログアウト・ログインし直すか、`sudo systemctl restart console-setup`を実行してください。

<details>
<summary>そもそもなぜUS配列で案内されることが多いのか</summary>

多くのLinuxディストリビューションのインストーラーや技術文書は、デフォルトで「English (US)」レイアウトを前提に書かれていることが多く、海外発の技術情報を検索・参照する機会が多いインフラエンジニアにとって、US配列に慣れておくこと自体にも実務上のメリットがあります。とはいえ、学習中に記号の入力ミスで消耗するくらいなら、**まずは物理キーボードに合わせて日本語配列で設定し、慣れてきたらUS配列に挑戦する**、という順序で問題ありません。

</details>

## まとめ

- Proxmox VEでのVM作成は、General→OS→System→Disks→CPU→Memory→Networkという各タブの設定を一通り確認して「Confirm」するだけで完了します。
- OSのインストールメディア(ISO)は配布元サイトからダウンロードし、Proxmoxの「ISO Images」からアップロードして使います。
- `sudo apt update`は「インストール」ではなく「利用可能なパッケージ情報の更新」であり、何かをインストールする前に実行するのが定石です。
- `sudo su -`でroot権限のシェルに切り替えられますが、実務では監査のしやすさから、コマンドごとに`sudo`を付ける運用の方が推奨されます。
- キーボードレイアウトの設定(日本語配列かUS配列か)は、手元の物理キーボードと一致させておくと、記号入力での混乱を避けられます。
