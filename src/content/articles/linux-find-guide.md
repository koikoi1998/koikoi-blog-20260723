## はじめに

- **この記事で得られること**: [BINDでDNSサーバーを構築するハンズオン](/articles/dns-server-handson-guide)のような手順書付きのハンズオンでは、編集するファイルのパスが毎回明示されています。しかし実務では、そのような手順書がない状態で「あのファイルはどこだったか」を自力で探し出す場面が日常的に発生します。この記事では、`find`コマンドを使って、ファイルやディレクトリを自力で探し当てる力を、実際に手を動かしながら鍛えます。
- **対象読者**: `find`コマンドを使ったことがない、あるいは名前は知っているが実際に検索条件を組み立てたことがない方を想定しています。

## ハンズオン手順

### Step 1: 名前の一部からファイルを探す

`bind`という文字列を含むファイルが、システム全体のどこにあるかを探してみます。

```bash
sudo find / -name "*bind*" 2>/dev/null
```

**`-name`オプションには、ワイルドカード(`*`)を使った部分一致のパターンを指定できます。** `2>/dev/null`は、権限がなくアクセスできないディレクトリで大量に出力される、`Permission denied`のエラーメッセージを画面から隠すためのおまじないです。この結果から、`/etc/bind/`という、いかにも設定が置かれていそうなディレクトリが見つかるはずです。

### Step 2: 種類と場所を絞り込む

見つかった`/etc/bind/`配下を対象に、ファイルだけ(ディレクトリを除く)を一覧表示してみます。

```bash
find /etc/bind -type f
```

**`-type f`はファイルだけ、`-type d`はディレクトリだけに絞り込むオプションです。** 探索対象のディレクトリを`/`から`/etc/bind`に絞り込むことで、検索範囲が狭まり、結果も見やすくなります。「まずは大まかに全体から探し、当たりを付けたら、そこを起点にさらに絞り込む」という段階的な探し方が、実務での基本です。

### Step 3: 更新日時で絞り込む

「直近で自分が編集したファイルはどれだったか」を、更新日時から探してみます。

```bash
find /etc/bind -mmin -30
```

**`-mmin -30`は、「30分以内に更新されたファイル」という条件です。** `-mtime -1`にすれば「1日以内」という指定になります。「さっき編集したはずなのに、どのファイルだったか忘れてしまった」というときに、この条件は非常に強力です。

### Step 4: 見つけたファイルに対して操作を実行する

`find`で見つけたファイルに対して、そのまま操作を実行してみます。

```bash
find /etc/bind -name "*.local" -exec cat {} \;
```

**`-exec`オプションを使うと、見つかったファイルそれぞれに対して、指定したコマンドを実行できます。** `{}`は「見つかったファイルのパスがここに入る」という意味のプレースホルダーで、末尾の`\;`は、`-exec`で実行するコマンドの終わりを示す、決まった書き方です。

## プロが見ている視点(上位1%の理解)

### ディレクトリ名から「そこに何がありそうか」を予想する力

`find`というコマンド自体の使い方以上に重要なのが、[/etcとLinuxのディレクトリ構成(FHS)を『上位1%』の視点で理解する](/articles/linux-filesystem-hierarchy-guide)で扱った、ディレクトリの命名慣習を理解しているかどうかです。設定ファイルなら`/etc`、ログなら`/var/log`、可変データなら`/var`、というFHS(Filesystem Hierarchy Standard)の慣習を頭に入れておけば、`find`で検索する前の時点で「おそらくこのあたりにあるはずだ」という当たりを付けられます。**`find`は、この「当たりを付ける力」を補強するための道具であり、当たりを付ける力そのものを代替するものではありません。** どちらも欠けていると、実務で必要なファイルへたどり着くまでに、無駄な時間がかかります。

### locate・treeという、findを補完するコマンド

`find`は実行するたびにファイルシステムを直接走査するため、対象範囲が広いと時間がかかります。**`locate`コマンドは、事前に作成されたファイル名の索引(データベース)を検索するため、`find`よりもはるかに高速**です。ただし、索引は定期的に(通常は1日1回)更新されるため、直近数分で作成されたファイルは見つからないことがあります。また、あるディレクトリ配下の構造を、階層構造のまま俯瞰したい場合は、`tree`コマンドが適しています。「速度重視で名前だけ探すなら`locate`」「階層構造を目で見たいなら`tree`」「細かい条件(更新日時、種類、そして`-exec`によるその場での操作)まで指定したいなら`find`」という使い分けが実務での基本です。

## よくある誤解・つまずきポイント

- **誤解1: 「findはlocateより高速なので、常にfindを使えばよい」**
  実際にはlocateの方が高速です。ただしlocateの索引は即時更新されないため、作成直後のファイルを探す場合はfindが必要です。
- **誤解2: 「`2>/dev/null`を付けないと、findコマンド自体が失敗する」**
  コマンド自体は失敗しません。`2>/dev/null`は、権限エラーのメッセージが大量に表示されて見づらくなることを防ぐための、見た目上の対策です。
- **誤解3: 「-execで実行できるのは、catのような読み取り専用のコマンドだけである」**
  `-exec`には、`rm`や`mv`のような、ファイルを変更・削除するコマンドも指定できます。ただし、意図しないファイルまで対象に含んでしまうと危険なため、まず`-exec`なしで対象ファイルの一覧を確認してから、`-exec`を追加することを推奨します。

## 障害・トラブルシューティングの視点

1. **findの結果が多すぎて見づらい**: 検索範囲(`/`ではなく`/etc`など)を絞り込むか、`-type f`のような条件を追加して絞り込みます。
2. **`Permission denied`が大量に表示される**: `2>/dev/null`を末尾に付けるか、`sudo`を付けて実行します。
3. **locateで最近作成したファイルが見つからない**: `sudo updatedb`を実行して索引を手動更新するか、直近のファイルであれば`find`を使います。

## まとめ

- `find`は、`-name`・`-type`・`-mmin`/`-mtime`といった条件を組み合わせて、ファイルシステムを直接検索するコマンドです。
- `-exec`を使うと、見つかったファイルに対してその場でコマンドを実行できます。
- `locate`は索引検索のため高速ですが、直近のファイルには対応できないことがあります。
- FHSの命名慣習を理解していることが、`find`で検索する前の「当たりを付ける力」につながります。

**今日から意識すべきこと**
1. ファイルのパスを忘れたときは、手順書を探す前に、まず`find`で自力で探し当てる習慣をつけましょう。
2. ディレクトリ名を見たら、FHSの慣習に照らして「ここには何が置かれていそうか」を考える癖をつけましょう。
