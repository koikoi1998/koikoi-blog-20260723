- **この記事で得られること**: [iSCSIの仕組み](/articles/iscsi-guide)は、SCSIコマンドをIPネットワーク上で実現する、**ブロックレベル**のストレージでした。この記事では、**ファイルレベル**という、まったく異なるレイヤーで動作する、NFS(**Network File System**)の仕組みを体系的に理解します。

## 全体像をつかむ

**iSCSIは、「ディスクそのもの」(ブロックデバイス)を、クライアントへ渡します。クライアント側は、受け取ったこのブロックデバイスに、自分でファイルシステムを作成し、管理する責任を負います。** **NFS(Network File System)は、これとはまったく異なるレイヤーで動作します。NFSサーバー自身が、すでにファイルシステムを管理しており、クライアントは、整理済みのディレクトリツリー(ファイルやフォルダ)を、そのまま受け取るだけ**でよいのです。

## 基礎から徹底解説

### 複数クライアントによる、同時アクセスの安全性が、根本的に異なる

**NFSは、複数のクライアントが、同じディレクトリを同時にマウントし、読み書きすることを、プロトコルレベルのロック機構で、自然にサポート**しています。**iSCSIで、同じLUN(ブロックデバイス)へ、複数のクライアントが無秩序に同時アクセスすると、クラスタ対応のファイルシステムを使っていない限り、データが破損する危険性**があります。この違いは、「複数のサーバーから、同じデータへ同時にアクセスしたい」という要件がある場合、どちらの仕組みを選ぶべきかを、直接左右します。

### NFSv3からNFSv4への進化:ステートレスから、ステートフルへ

**NFSv3は、プロトコル自体がステートレスであり、ファイルロックは、NLMという別の補助プロトコルが担当**していました。この構成では、mountd・NLM・NSMといった複数の補助サービスが、それぞれ別のポートを使い、ファイアウォール越しの運用が困難で、フェイルオーバー時には、古いロック情報が残る(stale lock)問題も抱えていました。**NFSv4は、ロックの仕組みをプロトコル自体に統合し、ステートフルな設計へと変わりました。** これにより、**通信は、TCPポート2049番、1つだけに集約**され、ファイアウォール越しの運用が、大幅に容易になりました。

<details>
<summary>NFSv4は、Kerberosによる暗号化にも標準で対応している</summary>

**NFSv4は、Kerberosによる認証・暗号化に、標準で対応**しています(利用自体は任意です)。**すべての通信が、ポート2049番という1つのポートに集約されているため、Kerberosを有効化すると、マウント操作やロック情報まで含めた、NFSの通信全体が暗号化される**ことになります。これは、NFSv3時代の、複数のポートに分散した補助プロトコルの構成では、実現が難しかった設計です。

</details>

## プロが見ている視点(上位1%の理解)

### 「ブロックか、ファイルか」という選択は、技術的な優劣ではなく、要件に対する適合性の問題

**iSCSIとNFSは、どちらが優れているかという、単純な優劣の関係にはありません。「クライアント側で、どのファイルシステムを使うかを自分で決めたい」のか、「複数のクライアントから、同じデータへ安全に同時アクセスしたい」のかという、要件そのものの違いが、どちらを選ぶべきかを決定**します。**「ストレージ」という1つの言葉の裏に、ブロックレベルとファイルレベルという、まったく異なる抽象化レイヤーが存在する**ことを理解していると、ストレージ技術の選定を、単なる好みではなく、要件に基づいた判断として行えるようになります。

## よくある誤解・つまずきポイント

- **誤解1: 「NFSとiSCSIは、どちらも同じレイヤーで動作する、似たような技術だ」**
  iSCSIはブロックレベル、NFSはファイルレベルという、まったく異なるレイヤーで動作する、別の技術です。
- **誤解2: 「iSCSIのLUNへは、複数のクライアントから安全に同時アクセスできる」**
  クラスタ対応のファイルシステムを使っていない限り、複数のクライアントによる同時アクセスは、データ破損の危険性があります。
- **誤解3: 「NFSv3とNFSv4は、ポート番号以外に大きな違いはない」**
  NFSv4は、ロックの仕組みをプロトコル自体に統合し、ステートレスからステートフルへと、設計そのものが変わっています。

## 障害・トラブルシューティングの視点

1. **複数のクライアントから、同じiSCSI LUNへアクセスしたら、データが破損した**: クラスタ対応のファイルシステムを使っていたか、あるいはNFSのような、ファイルレベルの仕組みを使うべきだったかを確認します。
2. **NFSv3が、ファイアウォール越しにうまく動作しない**: mountd・NLM・NSMといった補助サービスの、ポート開放設定を確認するか、NFSv4への移行を検討します。
3. **フェイルオーバー後、古いロックが残っていて、ファイルが開けない**: NFSv3のstale lock問題の可能性を確認し、NFSv4への移行を検討します。

## まとめ

- iSCSIは、ディスクそのもの(ブロックデバイス)を渡す、ブロックレベルのストレージです。
- NFSは、すでに整理されたディレクトリツリーを渡す、ファイルレベルのストレージです。
- iSCSIの同じLUNへの複数クライアントからの同時アクセスは危険ですが、NFSはこれを自然にサポートします。
- NFSv4は、ロックの仕組みをプロトコルへ統合し、ポート2049番への集約と、標準のKerberos対応を実現しています。

**今日から意識すべきこと**
1. 「複数のクライアントから、同じデータへ安全に同時アクセスしたい」という要件があるときは、NFSのようなファイルレベルの仕組みを検討しましょう。
2. 新規にNFSを導入する際は、NFSv3ではなく、NFSv4を選択しましょう。
